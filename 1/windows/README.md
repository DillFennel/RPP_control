# Заготовка самостоятельной работы: Windows, C++, TCP

Рабочая основа для тренировки. Реализован персональный счётчик с командами GET, SET, ADD, RESET и QUIT. Индивидуальный вариант ещё не известен: перед сдачей заменить команды, состояние и описание протокола под задание.

## Файлы и порядок изучения

```text
протокол.md              описание запросов, ответов, ошибок и framing
CMakeLists.txt           сборка двух отдельных программ
README.md               запуск, адаптация и вопросы к защите
server/
    main.cpp            socket → bind → listen → accept → обмен данными
    commands.hpp        состояние сессии и логика команд
client/
    main.cpp            socket → connect → отправка команд и разбор ответов
common/
    protocol.hpp        границы строк, числа, разбор ответов
    network.hpp         Winsock, send_all, read_line, освобождение ресурсов
```

Начать с `server/commands.hpp`, затем прочитать `server/main.cpp` и `client/main.cpp`. После этого разобраться с `extract_line`, `send_all` и `read_line`. В конце изучить вспомогательные классы `Socket` и `Winsock`.

Все исходники и документы сохранены в UTF-8. Интерфейс консоли и сетевые сообщения используют ASCII, чтобы запуск не зависел от кодовой страницы терминала Windows. Русские комментарии не передаются по сети.

## Сборка в Windows с MSVC и CMake

Нужны Visual Studio или Build Tools с инструментами разработки классических приложений на C++, Windows SDK и CMake. Сторонние библиотеки не используются.

Открыть Developer PowerShell / Developer Command Prompt для Visual Studio, перейти в корень этой заготовки и выполнить:

```powershell
cmake -S . -B build
cmake --build build --config Debug
```

При генераторе Visual Studio появятся `build\Debug\server.exe` и `build\Debug\client.exe`. При генераторе Ninja исполняемые файлы обычно лежат непосредственно в `build`.

В Visual Studio также можно открыть папку с `CMakeLists.txt` и собрать цели `server` и `client`.

### Сборка напрямую через cl, без CMake

В Developer PowerShell, из корня заготовки:

```powershell
cl /nologo /std:c++17 /EHsc /W4 /utf-8 server\main.cpp /Feserver.exe /Foserver.obj /link ws2_32.lib
cl /nologo /std:c++17 /EHsc /W4 /utf-8 client\main.cpp /Feclient.exe /Foclient.obj /link ws2_32.lib
```

`ws2_32.lib` нужна для Winsock. В этом способе сборки программы появятся в корне папки.

## Запуск

Для сборки CMake с генератором Visual Studio открыть два терминала в корне заготовки.

В первом:

```powershell
.\build\Debug\server.exe
```

Во втором:

```powershell
.\build\Debug\client.exe
```

Клиент по умолчанию подключается к 127.0.0.1:12345. Сервер привязан к INADDR_ANY:12345 и принимает подключения через локальные IPv4-интерфейсы. Для двух компьютеров передать IPv4-адрес сервера:

```powershell
.\build\Debug\client.exe 192.168.1.10
```

Для связи между компьютерами порт должен быть доступен через сеть и брандмауэр Windows. Адреса DNS в этой заготовке не поддерживаются.

В клиенте ввести по очереди:

```text
GET
SET 10
ADD 5
ADD abc
GET
RESET
QUIT
```

Ожидаемые результаты: 0, 10, 15, сообщение об ошибке, 15, 0, завершение сессии.
Запустить клиент повторно: GET снова вернёт 0.

Клиент заканчивает сессию по QUIT; Ctrl+Z и Enter также отправляют QUIT. Сервер останавливается по Ctrl+C: обработчик ставит флаг, основной код выходит из ожидания и закрывает сокеты. Ожидание готовности опрашивает флаг каждые 200 мс; если уже выполняется блокирующий send, выход может задержаться до его таймаута 5 секунд.

Сервер обслуживает одного клиента за раз. Пока один клиент подключён, другие могут подключиться на уровне TCP, но обработка их команд начнётся после завершения текущей сессии. Многопоточности в заготовке нет.

У приёма нет таймаута бездействия: незавершённая короткая строка будет ждать продолжения. Клиент тоже ждёт ответ сервера; при зависшем/недоступном ответе его можно завершить Ctrl+C. Это учебная модель с блокирующим обменом.

## Что менять под вариант

1. В `server/commands.hpp` заменить поля `Session`: например, на список чисел, баланс или строку.
2. Там же заменить `handle_command`: проверка команды, аргументов и затем действие. Сначала проверять все условия, потом изменять состояние.
3. При новых видах ответов обновить `parse_reply` в `common/protocol.hpp` и отображение в `client/main.cpp`. Для ответов `OK VALUE <integer>` текущий разбор уже подходит.
4. Обновить `протокол.md`: команды, форматы, ограничения, ошибки и примеры должны соответствовать коду.

Учебное изменение для защиты: добавить команду NEGATE, меняющую знак счётчика. Важно проверить минимальное значение int64: его положительный аналог не помещается в int64. Для ошибки можно использовать OVERFLOW; затем обновить протокол и подсказку клиента.

## Что нужно уметь объяснить

- `WSAStartup` включает Winsock для процесса, `WSACleanup` завершает использование библиотеки.
- В Windows сокет имеет тип `SOCKET`. Ошибки проверяются через `INVALID_SOCKET` и `SOCKET_ERROR`; код ошибки берётся из `WSAGetLastError`. `WSAStartup` возвращает свой код ошибки напрямую.
- `bind` назначает локальный адрес и порт сервера. В клиенте `connect` автоматически назначает локальный порт и устанавливает соединение с указанным удалённым адресом.
- `listen` готовит сокет к приёму подключений, `accept` создаёт отдельный сокет для общения с клиентом. Слушающий сокет продолжает существовать.
- `htons` и `htonl` переводят числа в сетевой порядок байтов. `inet_pton` преобразует IPv4-адрес из текста в двоичное представление.
- `send` может принять часть сообщения. `send_all` двигает позицию на фактически отправленное число байтов и продолжает отправку.
- Успех `send` не подтверждает выполнение команды сервером. Для этого клиент разбирает прикладной ответ `OK` или `ERR`.
- `recv` может вернуть часть строки или несколько строк. Он не добавляет `\0`; программа использует возвращённое количество байтов.
- `pending` хранит остаток потока. `extract_line` извлекает сообщение по LF и сохраняет байты следующих сообщений.
- `recv == 0` для TCP означает штатное завершение отправки другой стороной. Если остались байты без LF, сообщение считается незавершённым.
- `Session` создаётся внутри `serve_client`, поэтому значение не переносится между соединениями.
- `from_chars` разбирает число без исключений; проверка указателя конца запрещает `12abc`. Переполнение ADD проверяется до сложения.
- `Socket` — RAII-обёртка: деструктор вызывает `closesocket`, когда переменная выходит из области видимости. Копирование запрещено, чтобы один сокет не закрывался двумя владельцами.
- `select` ждёт готовности перед `recv` или `accept`. Короткий таймаут позволяет серверу заметить Ctrl+C. Это ожидание готовности, а не таймаут всей сессии.
- `shutdown(..., SD_SEND)` завершает направление отправки. Освобождение самого дескриптора выполняет `closesocket`.

## Сдача

Перед реализацией своего варианта отправить преподавателю его протокол. Перед сдачей сверить окончательный документ с поведением программы.
Тема обоих писем по требованиям: `Фамилия Имя, группа, вариант N`.
В архиве должны быть протокол в корне, папки `server` и `client`. Папка `common` также обязательна для сборки этой заготовки: её нельзя удалить из архива. Положить рядом CMakeLists.txt и README.md.

Пример упаковки из корня заготовки в PowerShell:

```powershell
Compress-Archive -Path .\протокол.md,.\README.md,.\CMakeLists.txt,.\server,.\client,.\common -DestinationPath .\submission.zip -Force
```

## Проверки и ограничения проверки

Переносимая часть проверена отдельно на macOS: успешно пройдены 108 проверок framing, чисел, команд, сохранения состояния при ошибках, изоляции сессий, переполнения и разбора ответов. Проверка собрана Clang в C++17 с предупреждениями как ошибками, AddressSanitizer и UndefinedBehaviorSanitizer; ошибок не выявлено. Проверки включали каждый размер фрагмента TCP-потока тестовой сессии, объединённые строки, разделённый CRLF, границу 1024 байта и крайние значения int64.

Сборка и запуск Windows-части Winsock в текущей среде не выполнены. Эти проверки не подтверждают работу сетевых вызовов Windows. Для окончательной проверки выполнить приведённые выше команды сборки и демонстрационную сессию на Windows.

При ручной проверке дополнительно отправить пустую команду, неизвестную команду, лишний аргумент, слишком большое число и отрицательное число. После каждой ошибки GET должен показывать прежнее значение. Проверить закрытие клиента, повторное подключение и Ctrl+C сервера.

Официальная справка: [recv](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-recv), [send](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-send), [closesocket](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-closesocket).
