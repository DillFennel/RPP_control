# Протокол TCP-счётчика

Учебный пример. Перед сдачей заменить команды под индивидуальный вариант.

## Соединение и сообщения

- TCP, IPv4, порт сервера 12345.
- После подключения сервер ждёт первую команду, приветствие не отправляет.
- Каждое сообщение заканчивается LF (\n). Принимается также CRLF (\r\n).
- Максимум 1024 байта содержимого без LF/CRLF.
- Содержимое: печатные ASCII-символы и табуляция. Остальные байты запрещены.
- Команды чувствительны к регистру. Аргументы разделяются пробелами/табуляциями; пробелы по краям допустимы.
- На одну полную команду — один ответ. Клиент ждёт ответ перед следующей командой.
- Сервер может принимать несколько команд подряд и обрабатывает их по порядку.
- После QUIT следующие команды этого соединения не выполняются.

## Состояние

В каждом соединении свой счётчик `long long`, начальное значение 0. На Windows и macOS в этих примерах это знаковое 64-битное число. После отключения состояние уничтожается. Клиенты обслуживаются последовательно.

Числовой аргумент — десятичное целое с необязательным знаком `+` или `-`. Ведущие нули допускаются. Диапазон: от -9223372036854775808 до 9223372036854775807. Дроби, экспонента и посторонние символы запрещены.

## Команды

| Запрос | Действие | Ответ |
| --- | --- | --- |
| GET | Прочитать значение | OK VALUE &lt;число&gt; |
| SET &lt;число&gt; | Установить значение | OK VALUE &lt;новое значение&gt; |
| ADD &lt;число&gt; | Прибавить число | OK VALUE &lt;новое значение&gt; |
| RESET | Установить 0 | OK VALUE 0 |
| QUIT | Закончить сессию | OK BYE, затем сервер закрывает соединение |

Ошибка не изменяет счётчик. Лишние или отсутствующие аргументы запрещены.

## Ошибки

Формат: `ERR <CODE> <description>`. Описание непустое, предназначено для человека; точный текст может меняться.

| CODE | Причина | Действие |
| --- | --- | --- |
| EMPTY_COMMAND | Пустая команда | Продолжить сессию |
| UNKNOWN_COMMAND | Неизвестная команда | Продолжить сессию |
| BAD_ARGUMENTS | Неверное количество аргументов | Продолжить сессию |
| BAD_NUMBER | Неверный формат числа или выход за диапазон int64 | Продолжить сессию |
| OVERFLOW | Результат ADD не помещается в int64 | Продолжить сессию |
| BAD_TEXT | Запрещённые байты | Продолжить сессию |
| LINE_TOO_LONG | Строка длиннее 1024 байт | Отправить ошибку и закрыть сессию |
| INCOMPLETE_MESSAGE | Конец передачи без LF после части команды | Отправить ошибку и закрыть сессию |

Слишком длинный запрос отклоняется сразу при обнаружении превышения. Если TCP-соединение уже оборвано, отправить ошибку может быть невозможно. EOF без незавершённого сообщения просто завершает сессию.

Порядок проверок: framing, допустимые символы, имя команды, количество аргументов, число, возможность операции. При некорректном числе, включая выход за диапазон, используется один код BAD_NUMBER.

## Примеры

Метки C/S в примерах не входят в сообщения. Каждая строка заканчивается LF.

### 1. Обычная сессия

```text
C: GET
S: OK VALUE 0
C: SET 10
S: OK VALUE 10
C: ADD -3
S: OK VALUE 7
C: QUIT
S: OK BYE
```

### 2. Ошибки

```text
C: SET 12
S: OK VALUE 12
C: ADD abc
S: ERR BAD_NUMBER Expected_integer_in_int64_range
C: GET
S: OK VALUE 12
C: SET 9223372036854775807
S: OK VALUE 9223372036854775807
C: ADD 1
S: ERR OVERFLOW Result_does_not_fit_int64
C: QUIT
S: OK BYE
```

### 3. Новое соединение

```text
C: GET
S: OK VALUE 0
C: SET +5
S: OK VALUE 5
C: RESET
S: OK VALUE 0
C: QUIT
S: OK BYE
```
