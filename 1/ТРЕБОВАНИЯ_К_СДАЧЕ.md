# Вариант 5: требования и порядок сдачи

## Соответствие заданию

| Требование | Реализация |
| --- | --- |
| Генерация строки заданного типа и длины | /generate; DIGITS, LETTERS, ALNUM, PUNCT; длина 1–128 |
| Установка seed | /seed; диапазон 0–4294967295 |
| Проверка строки по типу | /check; YES/NO по принадлежности символов алфавиту |
| Последние пять сгенерированных значений | /history; от старого к новому |
| Ошибки типа, длины, seed, формата | BAD_TYPE, BAD_LENGTH, BAD_SEED, BAD_FORMAT |
| TCP, C++, консольный клиент | Системный sockets API и стандартная библиотека C++17 |
| Состояние в памяти на сессию | Генератор и история создаются после accept |
| Сервер отвечает ошибкой на неверный ввод | ERR; обычные ошибки команд не завершают сессию |

Лимиты и точные имена команд выбраны для этой реализации, поскольку в варианте они не заданы.

## Протокол

На слайде требуется описать протокол и отправить преподавателю до разработки. Документ готов в протокол.md: команды, параметры, ответы, ошибки, границы сообщений и три примера обмена. Отправку письма выполняет студент; из этого проекта письма автоматически не отправляются.

## Итоговый архив

Выбрать одну платформу. Упаковать содержимое macos или windows, а не всю внешнюю папку:

```text
протокол.md
README.md
ПОЯСНЕНИЯ.md
CMakeLists.txt
SERVER/
    server.cpp
CLIENT/
    client.cpp
```

В корне ZIP должны быть протокол и папки SERVER/CLIENT. Команды упаковки находятся в платформенных README. Бинарные файлы и каталоги сборки не нужны. Другая платформа остаётся запасной версией.

Перед сдачей собрать и запустить выбранную версию по README, показать команды и обработку ошибок. Сборка и запуск варианта 5 в текущей работе не выполнялись.

На защите нужно понимать свой код и уметь изменить его. Пояснения и вопросы находятся в ПОЯСНЕНИЯ.md. По исходным требованиям: протокол — 4 балла, сервер — 10, клиент — 6; коэффициент понимания k равен доле правильных ответов, итог — 20 × k.
