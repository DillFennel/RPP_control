# Учебный протокол TCP-счётчика, версия 1

Это тренировочная заготовка. Перед сдачей заменить логику и этот документ под выданный вариант.

## Соединение и состояние

- Транспорт: TCP поверх IPv4, порт сервера 12345.
- Сервер принимает соединения последовательно: одновременно обслуживает одного клиента. Другие подключения могут ожидать в очереди.
- После подключения сервер не отправляет приветствие. Первое сообщение отправляет клиент.
- В каждой сессии хранится одно знаковое целое 64-битное число `value`, начальное значение 0.
- Состояние хранится только в памяти, принадлежит конкретному соединению и уничтожается при его завершении. Следующее соединение начинает с 0.

## Формат сообщений и framing

- Одно сообщение — одна строка, завершённая байтом LF (`\n`, 0x0A).
- Принимается также CRLF (`\r\n`): один CR непосредственно перед LF удаляется.
- Клиент и сервер этой реализации отправляют LF.
- Максимальная длина содержимого строки — 1024 байта, без LF или завершающего CRLF.
- Содержимое: печатные ASCII-символы 0x20–0x7E и табуляция 0x09. Встроенные NUL, CR и прочие управляющие байты запрещены.
- Команды и коды чувствительны к регистру: `GET` допустима, `get` неизвестна.
- Токены разделяются одним или несколькими пробелами/табуляциями. Пробелы и табуляции в начале и конце строки допускаются.
- В строковом аргументе нельзя передавать перевод строки: это всегда граница сообщения. В этой версии строковых аргументов нет.
- Сервер обрабатывает строки по порядку. В одном `recv` может оказаться часть строки или сразу несколько строк: незавершённый остаток сохраняется.
- На каждый полный запрос сервер отправляет один ответ. Клиент этой реализации ждёт ответ перед следующим запросом.
- После `QUIT` последующие команды этого соединения не выполняются.

## Числа

`integer` — десятичное целое с необязательным минусом: `0`, `15`, `-7`.
Ведущие нули допускаются. Знак `+`, дробная часть, экспонента и посторонние символы запрещены.
Диапазон: от -9223372036854775808 до 9223372036854775807 включительно.

## Команды и успешные ответы

| Запрос | Действие | Ответ |
| --- | --- | --- |
| `GET` | Прочитать текущее значение | `OK VALUE <integer>` |
| `SET <integer>` | Установить значение | `OK VALUE <новое значение>` |
| `ADD <integer>` | Прибавить число; отрицательный аргумент уменьшает значение | `OK VALUE <новое значение>` |
| `RESET` | Установить 0 | `OK VALUE 0` |
| `QUIT` | Завершить сессию | `OK BYE`, затем закрытие соединения сервером |

Лишние или отсутствующие аргументы являются ошибкой. При ошибке состояние не изменяется.

## Ошибки

Формат: `ERR <CODE> <description>`.
Клиент различает ошибку по `ERR`, её тип — по `CODE`. Непустое описание предназначено для человека; программа не должна полагаться на его точный текст.

| CODE | Причина | После ответа |
| --- | --- | --- |
| `EMPTY_COMMAND` | Пустая строка или только пробелы/табуляции | Сессия продолжается |
| `UNKNOWN_COMMAND` | Команда не входит в список | Сессия продолжается |
| `BAD_ARGUMENTS` | Неверное количество аргументов | Сессия продолжается |
| `BAD_NUMBER` | Аргумент не соответствует формату целого | Сессия продолжается |
| `NUMBER_RANGE` | Записанное целое выходит за границы int64 | Сессия продолжается |
| `OVERFLOW` | Результат ADD вышел бы за границы int64 | Сессия продолжается |
| `BAD_TEXT` | В строке есть запрещённые байты | Сессия продолжается |
| `LINE_TOO_LONG` | Содержимое строки превышает 1024 байта | Сервер закрывает сессию |
| `INCOMPLETE_MESSAGE` | Клиент завершил отправку, оставив строку без LF | Сервер закрывает сессию |

Порядок проверок: framing, допустимые байты, наличие/имя команды, количество аргументов, формат и диапазон числа, возможность выполнения операции.
Слишком длинный незавершённый запрос отклоняется, как только превышение можно обнаружить; LF для этого ждать не нужно.
При штатном EOF без незавершённой строки сервер просто заканчивает сессию. При сетевом обрыве отправить ответ может быть невозможно: сервер записывает ошибку и освобождает сокет.
При сетевой ошибке или таймауте отправки ответа сервер завершает только текущую сессию.

## Примеры сессий

Метки C/S ниже поясняют направление и не входят в сообщения. Каждая строка заканчивается LF.

### 1. Обычные операции

```text
C: GET
S: OK VALUE 0
C: SET 10
S: OK VALUE 10
C: ADD -3
S: OK VALUE 7
C: RESET
S: OK VALUE 0
C: QUIT
S: OK BYE
```

### 2. Ошибки не меняют значение

```text
C: SET 12
S: OK VALUE 12
C: ADD abc
S: ERR BAD_NUMBER Expected_decimal_integer_without_plus
C: GET extra
S: ERR BAD_ARGUMENTS This_command_takes_no_arguments
C: GET
S: OK VALUE 12
C: SET 9223372036854775807
S: OK VALUE 9223372036854775807
C: ADD 1
S: ERR OVERFLOW Addition_would_overflow_int64
C: QUIT
S: OK BYE
```

### 3. Новое соединение после завершения предыдущей сессии

```text
C: GET
S: OK VALUE 0
C: MUL 2
S: ERR UNKNOWN_COMMAND Supported_GET_SET_ADD_RESET_QUIT
C: QUIT
S: OK BYE
```
