# Заготовка самостоятельной работы для macOS: C++17 и TCP

Отдельный пример для macOS на POSIX-сокетах. Протокол и команды совпадают с Windows-заготовкой: GET, SET, ADD, RESET, QUIT. В каждой сессии свой счётчик, начальное значение 0. Перед сдачей заменить учебную логику под индивидуальный вариант.

## Сборка и запуск без CMake

Открыть Terminal и перейти в папку этой заготовки. Команды выполняются из папки, где лежат README.md и протокол.md.

Для компиляции нужен Apple Clang из Xcode Command Line Tools. Проверить его наличие:

```sh
clang++ --version
```

Если инструменты ещё не установлены, запустить `xcode-select --install` и завершить установку в появившемся окне.

Собрать две программы:

```sh
mkdir -p build
clang++ -std=c++17 -Wall -Wextra -Wpedantic server/main.cpp -o build/server
clang++ -std=c++17 -Wall -Wextra -Wpedantic client/main.cpp -o build/client
```

В первом терминале запустить сервер:

```sh
./build/server
```

Во втором терминале, из той же папки, запустить клиент:

```sh
./build/client
```

В клиенте ввести:

```text
GET
SET 10
ADD 5
ADD abc
GET
RESET
QUIT
```

Ожидаемый результат: 0, 10, 15, ошибка BAD_NUMBER, 15, 0, завершение сессии.
После повторного запуска клиента GET снова вернёт 0.

Клиент по умолчанию подключается к 127.0.0.1:12345. Для другого компьютера передать IPv4-адрес сервера:

```sh
./build/client 192.168.1.10
```

Сервер использует INADDR_ANY:12345. Для обмена между компьютерами порт должен быть доступен через сеть и брандмауэр. DNS-имена в этой заготовке не поддерживаются.

Для ручного обмена вместо клиента можно использовать `nc 127.0.0.1 12345`: вводить команды по одной и нажимать Enter. Сервер не присылает приветствие, он ждёт первую команду.

Клиент штатно заканчивает работу по QUIT или Ctrl+D в пустой строке. Сервер останавливается по Ctrl+C: обработчик устанавливает флаг, основной код освобождает сокеты.

## Сборка через CMake

Если CMake уже установлен:

```sh
cmake -S . -B build-cmake
cmake --build build-cmake
./build-cmake/server
```

Во втором терминале: `./build-cmake/client`.

## Файлы

```text
протокол.md              команды, ответы, ошибки, примеры, границы сообщений
CMakeLists.txt           сборка сервера и клиента
README.md               инструкции и пояснения
server/main.cpp         socket → bind → listen → accept → обработка сессии
server/commands.hpp     состояние Session и функция handle_command
client/main.cpp         socket → connect → запрос → ответ
common/protocol.hpp     framing, проверка чисел, разбор ответов
common/network.hpp      send_all, read_line, сигналы, закрытие сокетов
```

Начать изучение с `server/commands.hpp`, затем пройти `server/main.cpp` и `client/main.cpp`. После этого разобраться с `extract_line`, `send_all` и `read_line`.

## Отличия от Windows

| Windows | macOS |
| --- | --- |
| winsock2.h, ws2tcpip.h | sys/socket.h, netinet/in.h, arpa/inet.h, unistd.h |
| WSAStartup / WSACleanup | Инициализация библиотеки не нужна |
| SOCKET, INVALID_SOCKET | int, ошибка -1 |
| closesocket | close |
| WSAGetLastError | errno и strerror |
| shutdown(..., SD_SEND) | shutdown(..., SHUT_WR) |
| select игнорирует первый аргумент | select получает максимальный fd + 1 |
| SO_SNDTIMEO использует DWORD | SO_SNDTIMEO использует timeval |
| Ctrl+Z и Enter для конца консольного ввода | Ctrl+D в пустой строке |

На macOS при отправке в закрытое соединение возможен SIGPIPE. Опция SO_NOSIGPIPE переводит эту ситуацию в обычную ошибку send, которую программа обрабатывает. Прерванные сигналом системные вызовы могут вернуть EINTR: код повторяет операцию или завершает работу, если установлен флаг остановки.

## Что обеспечивает заготовка

- TCP с текстовыми строками, разделитель LF; CRLF также принимается.
- Незавершённые строки сохраняются между recv; несколько строк в одном recv разбираются отдельно.
- send_all досылает остаток, если send принял только часть данных.
- Максимальная длина строки — 1024 байта. Слишком длинная строка завершает только текущую сессию с ошибкой.
- Числа проверяются на формат, диапазон int64 и переполнение ADD до изменения состояния.
- Клиент разбирает ответы OK/ERR. Ошибка команды не изменяет состояние и не закрывает сессию.
- Деструктор Socket освобождает дескриптор при выходе из области видимости; копирование запрещено.

Сервер последовательно обслуживает одного клиента. Пока тот подключён, другие могут ожидать в очереди. Таймаута бездействия на приём нет: незавершённая короткая строка ждёт продолжения; клиент ждёт ответ. Таймаут одной блокирующей операции send — 5 секунд. Это учебная модель; многопоточности нет.

## Адаптация под вариант и защита

1. Изменить структуру `Session` и функцию `handle_command` в `server/commands.hpp`.
2. При добавлении нового формата ответа изменить `parse_reply` в `common/protocol.hpp` и его отображение в `client/main.cpp`.
3. Обновить `протокол.md`, включая аргументы, ответы, ограничения и примеры.

Уметь объяснить: bind задаёт локальный адрес, connect — удалённый; accept возвращает отдельный сокет; TCP передаёт поток байтов; recv не добавляет '\0'; ACK не означает выполнение команды; send_all учитывает частичную отправку; состояние сессии создаётся заново для каждого клиента.

Для тренировки добавить NEGATE: смену знака счётчика. Проверить крайний случай int64_min, который нельзя безопасно превратить в положительное значение.

## Упаковка для сдачи

Протокол должен быть в корне архива. Папки server, client и common нужны для сборки; CMakeLists.txt и README.md включают инструкции.

Из корня заготовки:

```sh
zip -r submission.zip протокол.md README.md CMakeLists.txt server client common
```

Протокол своего варианта отправить преподавателю до реализации. Тема письма по требованиям: `Фамилия Имя, группа, вариант N`. Перед сдачей сверить итоговый протокол с кодом.

## Выполненные проверки

Сервер и клиент собраны на macOS с Apple Clang 21 через CMake. Включены -Wall, -Wextra, -Wpedantic и -Werror; сборка прошла без предупреждений.

Проверены реально запущенные программы: успешно прошли 39 сетевых и консольных проверок. Среди них обычная сессия, ошибки команд, границы int64, сохранение состояния при ошибке, частичная передача строки и CRLF, несколько команд за одну отправку, размер 1024 байта, слишком длинная строка, EOF без LF, обрыв клиента, новое подключение со значением 0, конец консольного ввода, неверный адрес, отсутствие сервера, быстрый перезапуск, Ctrl+C при ожидании команды и SIGTERM.

Между двумя компьютерами обмен отдельно не проверялся; сетевые проверки выполнялись через 127.0.0.1.
