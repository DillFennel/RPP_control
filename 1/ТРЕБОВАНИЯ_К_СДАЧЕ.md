# Подготовка и сдача самостоятельной работы

Краткая памятка по предоставленным требованиям. Примеры в этом репозитории предназначены для подготовки; реализация сдаваемой работы должна соответствовать индивидуальному варианту преподавателя.

## До реализации варианта

Подготовить и отправить преподавателю протокол обмена. В нём должны быть:

- команды: имена, аргументы и назначение;
- формат успешных ответов и ошибок;
- framing: как определить конец каждого сообщения в TCP-потоке;
- перечень ошибок и способ их обозначения;
- 2–3 примера сессий, включая хотя бы один с ошибкой.

По документу должно быть возможно написать клиент без просмотра кода сервера. Имена команд и формат студент определяет самостоятельно. В примерах используется текстовый протокол со строками, заканчивающимися LF.

## Реализация

- Язык C++, транспорт TCP, интерфейс клиента консольный.
- Сервер обрабатывает некорректный ввод ошибкой и продолжает работу там, где это допускает протокол.
- Состояние хранится в памяти и относится к сессии клиента; между соединениями не сохраняется.
- Сборка воспроизводима: приложены CMakeLists.txt и команды непосредственной сборки.
- Если протокол меняется, исправить итоговый документ, включая ошибки, ограничения и примеры.

Использовать ИИ разрешается, но на защите нужно объяснить и при необходимости изменить любую часть кода.

## Архив

Выбрать одну платформу и упаковать содержимое её папки. Результат должен иметь такую структуру:

```text
протокол.md
README.md
CMakeLists.txt
server/
    main.cpp
    commands.hpp
client/
    main.cpp
common/
    network.hpp
    protocol.hpp
```

Протокол — строго в корне архива. В этой заготовке common тоже необходима: в ней общие заголовки. Исполняемые файлы, build, .git и служебные файлы IDE для сборки из исходников не нужны.

Один итоговый архив отправляется до конца пары. Тема письма как для протокола, так и для итогового архива:

```text
Фамилия Имя, группа, вариант N
```

## Защита

Нужно показать запуск сервера и клиента, выполнить команды, объяснить код и сделать небольшое изменение по просьбе преподавателя. Сервер могут проверить вручную по присланному протоколу.

Распределение баллов в требованиях: протокол — 4, сервер — 10, клиент — 6. Также задан коэффициент понимания `k = правильные ответы / общее число вопросов` и итог `20 × k`. Если студент не может объяснить код, коэффициент равен 0.

Перед защитой пройти вопросы из [пояснений](ПОЯСНЕНИЯ.md), выполнить успешную сессию и сессию с ошибками, проверить повторное подключение и обновить протокол после любых изменений.

## Что проверить перед отправкой

- Протокол был отправлен до разработки своего варианта.
- В архиве есть протокол в корне и папки server и client.
- Все необходимые исходники, включая common, добавлены.
- Тема письма содержит фамилию, имя, группу и вариант.
- Клиент умеет разбирать и показывать ошибки сервера.
- Ошибочная команда не меняет состояние и не обрушает сервер.
- Команды сборки и запуска подходят выбранной платформе.
- Окончательный протокол соответствует коду: именно по нему будут задавать вопросы.
